## 1. What a Train represents

A train is a physical vehicle in the metro fleet. It has:

- a system ID
- a train number
- capacity
- number of coaches
- manufacture year
- creation time
- active flag

Trains are assigned to schedules and can be the subject of maintenance issues.

---

## 2. Database table

```sql
CREATE TABLE "Trains" (
    "TrainID" VARCHAR(50) PRIMARY KEY,
    "TrainNumber" VARCHAR(50) NOT NULL,
    "Capacity" INTEGER,
    "TotalCoaches" INTEGER,
    "ManufactureYear" INTEGER,
    "CreatedAt" TIMESTAMP,
    "isActive" BOOLEAN DEFAULT TRUE
);

CREATE UNIQUE INDEX "UX_Train_Number" ON "Trains" ("TrainNumber");
```

| Column | Meaning |
|---|---|
| `TrainID` | Primary key, `TRN-<uuid>` |
| `TrainNumber` | Readable fleet number, e.g. `M1`, `A2`; unique |
| `Capacity` | Passenger capacity |
| `TotalCoaches` | Number of coaches |
| `ManufactureYear` | Year built |
| `CreatedAt` | When the row was created |
| `isActive` | Whether the train is in service |

## 3. Entity walkthrough

```java
@Entity
@Table(name = "\"Trains\"")
@JsonIgnoreProperties({"hibernateLazyInitializer", "handler"})
public class Train {

    @Id
    @Column(name = "\"TrainID\"", length = 50)
    private String trainId;

    @NotBlank(message = "Train number is required")
    @Column(name = "\"TrainNumber\"", length = 50, nullable = false)
    private String trainNumber;

    @Column(name = "\"Capacity\"")
    private Integer capacity;

    @Column(name = "\"TotalCoaches\"")
    private Integer totalCoaches;

    @Column(name = "\"ManufactureYear\"")
    private Integer manufactureYear;

    @Column(name = "\"CreatedAt\"")
    private LocalDateTime createdAt = LocalDateTime.now();

    @Column(name = "\"isActive\"")
    private Boolean isActive = true;
}
```

### Key points

- `trainId` is a string generated by the controller: `TRN-<uuid>`.
- `trainNumber` is the human-readable unique number.
- `createdAt` defaults to now if not provided.
- `isActive` defaults to true.
- `@NotBlank` on `trainNumber` is validated on create and update.
- There are no relations inside `Train`; other entities point to it.

### Why no `@ManyToOne`

A train does not own schedules or maintenance issues in the object model. Instead:

- `Schedule` has `train`
- `MaintenanceIssue` has `train`

This keeps `Train` simple and avoids bidirectional JSON recursion.

## 6. Method-by-method flow

### Create

```java
@PostMapping
@PreAuthorize("hasRole('ADMIN')")
@Transactional
public ResponseEntity<Train> createTrain(@Valid @RequestBody Train request) {
    Train train = new Train();
    train.setTrainId("TRN-" + UUID.randomUUID());
    copyTrainFields(request, train);
    return ResponseEntity.status(HttpStatus.CREATED)
        .body(trainRepository.save(train));
}
```

`copyTrainFields`:

```java
train.setTrainNumber(request.getTrainNumber());
train.setCapacity(request.getCapacity());
train.setTotalCoaches(request.getTotalCoaches());
train.setManufactureYear(request.getManufactureYear());
if (request.getIsActive() != null) {
    train.setIsActive(request.getIsActive());
}
```

Steps:

1. Admin role check.
2. Validation of `trainNumber`.
3. Generate `TRN-<uuid>`.
4. Copy editable fields.
5. Save.
6. Return `201`.

### Update

1. Load by ID.
2. Throw `Train not found` if missing.
3. Copy fields.
4. Save.
5. Return `200`.

### Read

- `GET /api/trains/{id}` returns one train.
- `GET /api/trains` returns all trains.

Both require authentication but no specific role.

### Delete

1. Check existence.
2. `deleteById`.
3. Return `204`.

If a schedule or maintenance issue references the train, PostgreSQL rejects the delete because of foreign keys.

## 8. Relations to other groups

### Schedule

```java
Schedule.train -> Train
```

A schedule says which train runs which route and when. The database enforces `TrainID NOT NULL` on schedules.

Overlap logic in `ScheduleRepository` checks:

```sql
s.train.trainId = :trainId
AND s.scheduledDeparture < :arrivalTime
AND s.scheduledArrival > :departureTime
```

So the same train cannot have two overlapping schedules.

### MaintenanceIssue

```java
MaintenanceIssue.train -> Train
```

A maintenance issue can point to a train. The relation is optional; an issue may instead point to a station.

Deleting a train with schedules or issues fails due to foreign keys.

## 12. Viva questions

**Q: Why does Train not have a list of schedules?**
A: The relation is unidirectional from Schedule to Train. Keeping it one-way avoids infinite JSON loops and unnecessary loading.

**Q: Why is train number unique?**
A: It is the fleet's human-readable identifier.

**Q: Why use `Integer` for capacity?**
A: Capacity is a whole number. `Integer` is sufficient; `BigDecimal` is reserved for money.

**Q: Why is `createdAt` set in the entity?**
A: It provides a default timestamp. The controller does not explicitly set it on create, so the field initializer supplies `LocalDateTime.now()`.

**Q: What happens if a train is inactive?**
A: The flag is stored, but schedule creation does not currently reject inactive trains. It is a data/status flag, not an enforcement rule.

**Q: Can a train have two schedules at the same time?**
A: No. `ScheduleRepository.hasOverlappingSchedule` checks time overlap for the same train.

**Q: What happens if I delete a train used by a schedule?**
A: PostgreSQL rejects it because of the foreign key. Delete the schedule first.

**Q: Why no `@NotBlank` on capacity?**
A: Capacity is optional in the schema. Only the train number is mandatory.

**Q: Where is the train used in a ticket?**
A: Tickets do not reference trains directly. A ticket references a fare and stations; schedules connect trains to routes and times.

**Q: How would you add train type?**
A: Add a column in a new Flyway migration, add the field to the entity, and copy it in `copyTrainFields`.

## 13. One-line summary

`Train` is the fleet record: it stores the unique train number, capacity, coaches, and status, and it is referenced by schedules and maintenance issues.
